# Snippet Saver UI Rework Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rework the manager UI after first hands-on use: copy from the list, two views (toolbar popup = list only, window = full manager), tag manager, new button layout, Save only when changed.

**Architecture:** Same `popup/popup.html` page with two views chosen by URL: `?view=window` (opened by the service worker) = full manager; no parameter = toolbar popup = list only. Store gains tag operations that rewrite `meta` only. Content is still read only to edit, paste, search and export.

**Tech Stack:** Vanilla JS ES modules, MV3, `node --test`.

**Spec:** `docs/spec.md` (v1 plus the changes below; Task 7 updates it). Earlier plan: `docs/superpowers/plans/2026-11-16-snippet-saver-v1.md`.

## Global Constraints

- Everything in the v1 plan's Global Constraints still holds, except: `optional_host_permissions` for http(s) are added in Task 6 (no `host_permissions`, no install warning); the toolbar popup and the window are no longer the same layout (spec #5 changes), and the left list no longer selects on a name click.
- Never read all snippet content except for Export. Tag operations touch `meta` only.
- Storage layout: `meta` array + `c:<id>` content keys (unchanged).
- No `confirm()`/`alert()`; inline confirmations only.
- Window view fixed 600 x 445 px content (SW opens it at 616 x 490 outer). Toolbar popup width 360 px, height 445 px.
- Copy feedback text: `"Copied!"` (about 1 s). Copy failure text: `"Copy failed"`.
- Commit messages plain, no attribution lines (user preference).

## User decisions this plan implements (2026-11-17)

- Name in the list is underlined; clicking it copies the content and shows `"Copied!"` in place of the name. Clicking the rest of the row selects it for editing (window view).
- Toolbar popup: list only (search, tag filter, list). Click copies, shows `"Copied!"`, then closes the popup. A button opens the manager window. Window: full layout.
- Right pane: after the "Content" label a link `"Copy content"` (same copy and feedback). Save button inside the right pane under the text area. The old Copy button is removed.
- Save is disabled until name, tags or content of the open snippet differ from what was loaded.
- Left pane is a wrapper like the right pane; New and Delete sit under the list inside it; Data button at bottom left under both wrappers.
- Simple tag manager: list of tags, Rename and Delete, applied to all snippets.

## Plan decisions to confirm (not fixed by the user)

- Toolbar popup: the whole row (not just the name) copies and closes, since there is no editor there.
- Footer (below the wrappers): `[Data] [Tags]` on the left; the inline confirm row (Delete, Unsaved changes) appears in the footer on the right.
- "Tags" button in the footer opens the tag manager in the right pane (window view only); guarded by the unsaved-changes prompt.
- Rename onto an existing tag (case-insensitive) merges into the existing spelling. Case-only rename changes the spelling.
- Left and right wrappers share the same border, radius, padding and background.
- Data menu opens upward (button is at the bottom).

## Review Focus

1. Rename tag onto a name that already exists (case-insensitive) in the same snippet: no duplicate tags. (Task 1)
2. Empty or whitespace-only new tag name; rename or delete of a tag that no snippet has: rejected / no-op, no write. (Task 1)
3. Copy of a snippet that was deleted after the list rendered: no "Copied!", visible "Copy failed", no throw. (Task 3)
4. Toolbar popup closes only after the clipboard write finished. (Task 4)
5. Save state: disabled after load, after successful Save, after discard; enabled in New mode once anything is typed and for prefilled "Add as snippet". (Task 2)
6. A frame origin that is not http(s), or a malformed frame URL: no throw, visible feedback. (Task 6)
7. Opening the tag manager or "Open manager" with unsaved edits: guarded, nothing lost. (Tasks 4, 5)

### Task 1: Tag operations in the store

**Files:** Modify `extension/lib/store.js`; Test `test/store.test.js`

**Interfaces:**
- Consumes: `normalizeTags` from `tags.js`.
- Produces on the store object:
  - `renameTag(from: string, to: string): Promise<number>` — number of snippets changed. Throws `StoreError("TAG_REQUIRED")` when `to` is empty after trim. Matching of `from` is case-insensitive. If `to` matches another existing tag case-insensitively, that tag's spelling is used (merge). Case-only change of the same tag keeps the typed spelling. Per snippet, result goes through `normalizeTags(tags, [])` so no duplicates remain.
  - `deleteTag(tag: string): Promise<number>` — removes the tag from every snippet, case-insensitive, returns count changed.
  - Both read and write `meta` only (no `c:` key read).

- [ ] **Step 1: Write failing tests** (names and assertions):
  - `renameTag changes the tag on all snippets, returns the count`: tags `["a"]`, `["a","b"]`, `["c"]`; `renameTag("a","z")` → 2; metas tags `["z"]`, `["z","b"]`, `["c"]`.
  - `renameTag merges into an existing tag, no duplicates in one snippet`: `["Work","work2"]`... use snippets `["Foo","Bar"]` and `["foo"]`; `renameTag("Foo","bar")` → result tags `["Bar"]` and `["Bar"]` (existing spelling wins).
  - `renameTag allows a case-only change`: `["foo"]`, `renameTag("foo","Foo")` → `["Foo"]`.
  - `renameTag rejects empty or whitespace target` with `TAG_REQUIRED` and writes nothing.
  - `renameTag of an unknown tag returns 0 and does not write` (spy on `area.set` count).
  - `deleteTag removes case-insensitively and returns count`.
  - `tag operations read no content keys` (`contentKeysRead(area)` empty).
- [ ] **Step 2: Run** `node --test test/store.test.js`. Expected: FAIL (functions missing).
- [ ] **Step 3: Implement** both in `store.js` using `readMeta` and one `area.set({ meta })`; skip the write when nothing changed. `modified` is not touched.
- [ ] **Step 4: Run** `npm test`. Expected: PASS.
- [ ] **Step 5: Commit** `feat: tag rename and delete`.

### Task 6: Paste snippet in cross-origin iframes (Workfront)

**Cause (confirmed by the user's SW console, 2026-11-17):** `executeScript` into the Workfront iframe is refused: "Cannot access contents of the page. Extension manifest must request permission to access the respective host." `activeTab` covers the top page only, not a cross-origin frame. The error was only `console.warn`-ed, so nothing showed.

**User decision:** both a no-permission fallback and an opt-in per-site permission.

**Files:** Modify `extension/manifest.json`, `extension/background/sw.js`, `extension/lib/overlay.js`; Create `extension/lib/paste-target.js`; Test `test/manifest.test.js`, `test/paste-target.test.js`, `test/overlay.test.js`

**Interfaces:**
- Produces in `lib/paste-target.js`:
  - `originPattern(url: string): string | null` — `"https://x.example.com/*"` style pattern for http(s) URLs, `null` for anything else (`chrome://`, `about:`, malformed).
  - `isPermissionError(err): boolean` — true when the message matches "Cannot access contents" or "Extension manifest must request permission".
- `openPalette(metas, { copyOnly = false } = {})` — with `copyOnly`, picking a snippet skips insertion: it copies and shows the toast `"Copied. Press Ctrl+V"`.
- Manifest: `optional_host_permissions: ["https://*/*", "http://*/*"]`; still no `host_permissions`; no install-time warning.
- Menus: add `allow` ("Allow Snippets on this site", contexts `["editable"]`). Click → `chrome.permissions.request({ origins: [originPattern(info.frameUrl)] })`; result shown through the toolbar badge (`"OK"` or `"!"`, cleared after 3 s).
- Paste flow in `sw.js`: try the clicked frame; on a permission error, inject the palette into the top frame (`frameIds: [0]`) with `copyOnly: true`; if that also fails, show badge `"!"` with title `"Snippets unavailable on this page"` for 3 s (visible instead of silent).

- [ ] **Step 1: Write failing tests:**
  - `originPattern("https://a.example.com/x?y=1")` → `"https://a.example.com/*"`; `originPattern("chrome://extensions")` → `null`; `originPattern("not a url")` → `null`; `originPattern("http://localhost:3000/p")` → `"http://localhost/*"` (Chrome host patterns ignore ports).
  - `isPermissionError(new Error("Cannot access contents of the page. Extension manifest must request permission to access the respective host."))` → true; `isPermissionError(new Error("boom"))` → false.
  - Manifest test: `host_permissions` undefined and `optional_host_permissions` deep-equals the two patterns.
  - Overlay test: with `{ copyOnly: true }`, picking a row with a focused fake `textarea` as `document.activeElement` copies and does not call `execCommand`.
- [ ] **Step 2: Run** `npm test`. Expected: FAIL.
- [ ] **Step 3: Implement** `paste-target.js`, the manifest change, and the `copyOnly` option in `overlay.js`.
- [ ] **Step 4: Implement** the paste flow and the `allow` menu item in `sw.js` (menus recreated in `onInstalled`; badge helper `flashBadge(text, title)`).
- [ ] **Step 5: Run** `npm test`. Expected: PASS.
- [ ] **Step 6: Manual check** (user, reload the extension): on Workfront, right-click in the field → Paste snippet → palette appears on the top page, pick copies and shows the toast; right-click → "Allow Snippets on this site" → Chrome prompts → grant; then Paste snippet inserts directly into the field. On `chrome://extensions` a right-click gives badge `"!"`. Verify whether the context-menu click counts as the user gesture `permissions.request` needs; if not, raise as an inflection point.
